# Independent Spaces

Windows 11에서 **모니터마다 별도의 데스크톱을 전환**하는 실험용 데스크톱 앱입니다. 예를 들어 왼쪽 모니터만 `Desktop 1 → Desktop 2`로 바꾸고, 오른쪽 모니터의 창은 그대로 유지할 수 있습니다.

이 앱은 실행 중인 창을 모니터별 작업 공간에 배정하고 표시·숨김을 제어합니다. `Win + Tab`에는 앱이 만든 작업 보기를 열어 모든 모니터의 데스크톱과 각 데스크톱의 **창 제목 목록**을 보여 줍니다. Windows 기본 가상 데스크톱이나 기본 작업 보기 화면을 수정하는 구현은 아닙니다.

## 빠른 시작

요구 환경은 Windows 11 x64입니다. 소스를 빌드하려면 .NET 10 SDK가 필요합니다. PowerShell에서 저장소 폴더로 이동한 뒤 실행하세요.

```powershell
.\scripts\build.ps1 -Publish
.\artifacts\publish\IndependentVirtualDesktop.exe
```

`artifacts\publish`는 .NET 런타임을 포함합니다. 다른 PC로 옮길 때는 실행 파일만이 아니라 **폴더 전체**를 복사하세요. 앱은 일반 사용자 권한으로 실행합니다.

SDK가 설치된 개발 환경에서는 다음 명령으로 바로 실행할 수도 있습니다.

```powershell
dotnet run --project .\src\IndependentVirtualDesktop.App\IndependentVirtualDesktop.App.csproj -c Release
```

실행하면 작업 보기와 알림 영역 아이콘이 나타납니다. 현재 보이는 일반 앱 창이 해당 모니터의 첫 데스크톱에 배정됩니다. 처음에는 Windows 기본 가상 데스크톱을 하나만 사용하는 환경에서 시작하는 것을 권장합니다.

## 사용 방법

| 동작 | 단축키 | 적용 대상 |
| --- | --- | --- |
| 자체 작업 보기 열기 / 닫기 | `Win + Tab` | 마우스가 있는 모니터에 열리며 모든 모니터를 표시 |
| 이전 / 다음 데스크톱 | `Win + Ctrl + ← / →` | 마우스가 있는 모니터 |
| 데스크톱 추가 후 전환 | `Win + Ctrl + D` | 마우스가 있는 모니터 |
| 현재 데스크톱 삭제 | `Win + Ctrl + F4` | 마우스가 있는 모니터 |
| 현재 창을 이전 / 다음 데스크톱으로 이동 | `Win + Ctrl + Shift + ← / →` | 전경 창이 속한 모니터 |
| 모든 관리 창 복구 후 일시 정지 | `Win + Ctrl + Shift + F12` | 모든 모니터 |
| 작업 보기 닫기 | `Esc` | 작업 보기에 포커스가 있을 때 |

마지막 데스크톱에서 다음으로 전환하면 첫 데스크톱으로 돌아갑니다. 창 이동 단축키는 창의 배정만 바꾸므로 대상 데스크톱으로 자동 전환하지 않습니다.

작업 보기에서는 다음과 같이 조작합니다.

- 모니터 행의 **+ 데스크톱 추가**로 새 데스크톱을 만들고 전환합니다.
- 데스크톱 제목을 클릭하면 해당 모니터만 전환합니다. 제목을 우클릭하면 이름 변경과 삭제 메뉴가 나옵니다.
- 창 제목을 클릭하면 창이 있는 데스크톱으로 전환하고 해당 창의 활성화를 요청합니다. Windows의 포커스 정책에 따라 활성화가 제한될 수 있습니다.
- 창 제목을 우클릭하면 같은 모니터의 다른 데스크톱으로 이동할 수 있습니다. 연결된 대화상자와 보조 창도 함께 이동합니다.
- 창을 다른 물리 모니터로 끌어 놓으면 그 모니터의 현재 데스크톱으로 배정됩니다.

모니터마다 데스크톱은 최소 하나 유지됩니다. 데스크톱을 삭제하면 그 안의 창은 이전 데스크톱으로 이동하며, 첫 데스크톱을 삭제할 때는 다음 데스크톱으로 이동합니다. 모니터 연결이 해제되면 그 모니터에 배정된 창은 남은 주 모니터의 현재 데스크톱으로 배정됩니다.

## 종료와 창 복구

작업 보기의 닫기 버튼과 `Esc`는 작업 보기만 닫습니다. 앱을 종료하려면 알림 영역 아이콘을 우클릭하고 **종료 · 모든 창 복구**를 선택하세요. 아이콘이 보이지 않으면 알림 영역의 숨겨진 아이콘 목록을 확인하세요.

**일시 정지 / 다시 시작**은 창 숨김을 멈추고 관리 창을 표시합니다. 배정은 메모리에 유지되며 다시 시작하면 적용됩니다. 일시 정지 중에도 단축키는 앱이 처리합니다. Windows 기본 `Win + Tab` 동작을 사용하려면 앱을 종료하세요.

앱은 창을 숨기기 전에 복구 정보를 기록하고, 별도 감시 프로세스가 앱 종료를 감지하면 숨긴 창의 복구를 시도합니다. 감시 프로세스가 중단되면 본 앱은 관리 창을 복구하고 일시 정지합니다. 앱이 비정상 종료된 후에도 창이 남아 있으면 다음 명령으로 복구를 다시 시도할 수 있습니다.

```powershell
.\artifacts\publish\IndependentVirtualDesktop.exe --recover
```

`--recover`는 이미 종료된 앱의 복구 기록만 처리합니다. 기록은 `%LOCALAPPDATA%\IndependentVirtualDesktop\recovery`, 오류 로그는 `%LOCALAPPDATA%\IndependentVirtualDesktop\app.log`에 있습니다. 응답하지 않는 창의 복구가 완료되지 않으면 기록을 남겨 다음 시도에 사용합니다.

## 현재 범위와 제한

- **실행 세션 단위**입니다. 데스크톱 개수, 이름, 창 배정은 앱 종료 후 저장되지 않습니다. 복구 기록은 창을 되살리기 위한 정보이며 작업 공간 저장 기능이 아닙니다.
- Windows 기본 가상 데스크톱과 별개의 공간입니다. 기본 작업 보기 버튼이나 터치패드 제스처로 여는 Windows 화면에는 이 앱의 데스크톱이 나타나지 않습니다. 기본 데스크톱 하나에서 사용하는 것을 권장합니다.
- 새 창과 모니터 이동을 약 **500ms 주기**로 발견합니다. 완전한 실시간 전환이나 화면 깜빡임 방지를 보장하지 않습니다.
- 작업 보기는 창 제목 목록입니다. 실시간 미리보기, Windows 작업 보기의 애니메이션, 모니터별 배경화면, 독립적인 작업 표시줄은 구현하지 않았습니다.
- 관리자 권한 앱처럼 프로세스 정보를 확인할 수 없거나 창에 복구 표시를 설정할 수 없는 창은 제어 대상에서 제외되거나 **제어 불가**로 표시됩니다. 이런 창은 데스크톱 전환 시 그대로 보일 수 있습니다.
- 쉘 창, 시스템 UI, 일반 앱 창으로 식별되지 않는 일부 창은 관리하지 않습니다. 전체 화면 게임, 특수 렌더링 앱, 보안 데스크톱 등은 지원을 검증하지 않았습니다.
- 단축키는 키보드 훅으로 처리합니다. 다른 단축키 도구, 권한 차이, 입력 환경에 따른 충돌 가능성이 있습니다. 키 입력 판별 로직은 자동 검증했지만 실제 키보드의 전역 단축키 동작은 수동 확인이 필요합니다.

## 빌드와 테스트

```powershell
.\scripts\build.ps1
.\scripts\test.ps1
```

`build.ps1`은 솔루션을 Release로 빌드합니다. `-Publish`를 추가하면 `win-x64` 독립 실행 배포 폴더도 만듭니다. 이미 빌드했다면 `test.ps1 -SkipBuild`로 빌드를 생략할 수 있습니다.

동일한 기본 명령은 다음과 같습니다.

```powershell
dotnet build .\IndependentVirtualDesktop.sln -c Release
dotnet run --project .\tests\IndependentVirtualDesktop.Core.Tests\IndependentVirtualDesktop.Core.Tests.csproj -c Release --no-build
dotnet publish .\src\IndependentVirtualDesktop.App\IndependentVirtualDesktop.App.csproj --self-contained true -r win-x64 -c Release -o .\artifacts\publish
```

테스트 스크립트는 코어의 모니터 독립성·창 배정·삭제·연결 해제·잘못된 입력을 검사한 뒤, 앱의 `--self-test`를 실행합니다. 앱 테스트는 임시 테스트 창을 띄워 그 창만 제어하며 실제 키보드 훅을 설치하지 않습니다. 데스크톱 UI에 접근할 수 있는 Windows 사용자 세션에서 실행하세요.

앱 테스트 결과와 작업 보기 렌더링 이미지는 `artifacts\tests\smoke-results.txt`, `artifacts\tests\overview.png`에 생성됩니다. 두 물리 모니터에서 전용 테스트 창을 사용해 한쪽 전환 시 다른 쪽 창 유지, 소유 대화상자 동반 이동, 최소화 상태 유지, 관리 프로세스 강제 종료 후 감시 프로세스 복구를 확인했습니다. 코어 테스트 11개와 단축키 판별 테스트 9개도 통과했습니다. 실제 사용자 앱 전체와 실제 키보드 입력에 대한 호환성 검증은 별도로 필요합니다.

구현 구조는 [docs/architecture.md](docs/architecture.md)에 정리했습니다.
