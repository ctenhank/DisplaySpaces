# 구현 구조

## 작업 공간 모델

`IndependentVirtualDesktop.Core`는 Windows API에 의존하지 않는 .NET 10 라이브러리입니다. `WorkspaceCatalog`가 디스플레이별 데스크톱 목록과 활성 데스크톱 ID, 창별 배정을 소유합니다. 창이 속한 데스크톱과 해당 디스플레이의 활성 데스크톱이 같으면 논리적으로 표시할 창입니다.

| 모델 | 의미 |
| --- | --- |
| `DisplayDescriptor` | OS에서 발견한 디스플레이의 ID, 이름, 주 모니터 여부 |
| `WindowAssignment` | 창 핸들, 디스플레이 ID, 데스크톱 ID |
| `DesktopSnapshot` | 데스크톱 ID와 이름, 배정된 창 ID 목록 |
| `DisplaySnapshot` | 디스플레이 정보와 현재 데스크톱 ID, 데스크톱 목록 |

데스크톱 ID는 `Guid`, 창 ID는 `IntPtr.ToInt64()`에 대응하는 `long`입니다. 0인 창 ID는 거부하며, 부호 있는 포인터 표현을 보존하기 위해 음수인 비영 값도 허용합니다. 스냅샷은 내부 컬렉션과 분리된 읽기 전용 자료입니다. 카탈로그의 접근은 잠금으로 직렬화합니다.

모니터 목록을 동기화할 때 입력 전체를 검증한 뒤 반영합니다. 빈 목록이나 중복 ID처럼 잘못된 입력은 현재 상태를 바꾸지 않습니다. 연결이 유지된 모니터는 데스크톱 구성을 유지하고, 새 모니터는 데스크톱 하나로 시작합니다. 연결 해제된 모니터의 모든 창은 남은 주 모니터의 활성 데스크톱으로 이동합니다. 주 모니터가 없다면 입력 목록의 첫 모니터를 사용합니다.

새 창의 발견은 `TrackWindow`가 처리하며, 이미 알려진 창을 다시 발견해도 배정을 바꾸지 않습니다. 다른 모니터로 이동한 창에는 `AssignToDisplay`를 사용합니다. 데스크톱 삭제는 창을 이전 데스크톱으로 옮기고, 첫 데스크톱이면 다음 데스크톱을 사용합니다. 마지막 데스크톱 삭제는 거부합니다. 상대 전환은 양방향으로 순환하며 `int` 전체 범위를 처리합니다.

## Windows 창 제어

`IndependentVirtualDesktop.App`은 .NET 10 Windows Forms 앱입니다. 다음 순서로 사용자 창을 관리합니다.

1. `DesktopApplicationContext`의 500ms 타이머가 `DesktopController.Refresh`를 호출합니다.
2. `Screen.AllScreens`로 모니터를 동기화하고 `NativeWindows.EnumerateWindows`로 일반 앱 창과 연결된 대화상자를 수집합니다.
3. 새 창은 현재 Windows 기본 가상 데스크톱에 속하고 화면에 보이는 경우에만 등록합니다. 자체 앱 창, 쉘 창, 독립적인 도구 창 등은 제외합니다.
4. 창의 모니터 이동과 소유자 관계를 반영합니다. 연결된 대화상자와 보조 창은 소유자 창의 작업 공간을 따릅니다.
5. 카탈로그의 논리적 표시 상태를 `ShowWindowAsync`의 표시·숨김 요청으로 반영합니다.

Windows 공개 `IVirtualDesktopManager.IsWindowOnCurrentVirtualDesktop`는 현재 기본 데스크톱 여부를 확인하는 용도로만 사용합니다. Windows의 기본 가상 데스크톱을 생성·전환하거나 Explorer 작업 보기를 수정하지 않습니다. 이 앱의 데스크톱은 창 배정과 표시 상태로 구현한 별도의 작업 공간입니다.

창은 핸들만으로 식별하지 않습니다. 프로세스 ID, 프로세스 시작 시간, 창 클래스를 함께 확인합니다. 숨길 창에는 임의의 복구 표식을 `SetProp`으로 설정합니다. 프로세스 정보를 읽을 수 없거나 `SetProp`이 거부되면 해당 창을 숨기지 않습니다. 연결된 창 그룹의 일부를 안전하게 기록할 수 없으면 그룹 전체의 숨김을 피합니다. 따라서 일반 권한 앱에서 관리자 권한 창을 완전히 관리할 수 있다고 가정하지 않습니다.

`ShowWindowAsync`는 요청을 전달하는 API이므로 반환만으로 복구 완료를 판단하지 않습니다. 후속 가시성 확인까지 복구 기록을 유지합니다. 원래 최소화되어 있던 창은 최소화 상태로 복구하고, 일반·최대화 창은 저장된 배치를 유지하는 표시 방식을 사용합니다. 창 활성화는 Windows의 전경 활성화 정책에 영향을 받습니다.

## 작업 보기와 입력

`OverviewForm`은 마우스가 위치한 모니터에 열리는 하나의 창입니다. 모든 모니터를 행으로, 각 모니터의 데스크톱을 카드로 표시하며 창 제목을 나열합니다. 실시간 창 미리보기는 사용하지 않습니다. 데스크톱 제목을 우클릭하면 이름 변경·삭제 메뉴, 창 제목을 우클릭하면 같은 모니터 내 이동 메뉴가 열립니다.

`KeyboardHook`는 별도 메시지 루프 스레드에서 저수준 키보드 훅을 실행합니다. `KeyboardShortcutState`가 물리 키의 눌림·떼짐 상태를 해석하고 명령을 발행하며, 명령은 UI 스레드로 전달됩니다. 주입된 키 입력은 단축키 판정에 사용하지 않습니다. 훅 콜백은 창 열거와 복구 파일 쓰기 작업을 직접 수행하지 않습니다.

데스크톱 전환·추가·삭제는 마우스가 위치한 모니터를 대상으로 합니다. 창 이동 단축키는 전경 창의 기존 배정을 기준으로 대상을 정합니다. 작업 보기의 창 선택은 해당 데스크톱으로 전환하지만, 창 이동 자체는 데스크톱 전환을 동반하지 않습니다.

일시 정지는 창 표시 정책만 바꿉니다. 키보드 훅은 앱 종료까지 유지되므로 기본 Windows 단축키로 돌아가려면 앱을 종료해야 합니다. 작업 보기의 닫기 버튼은 창을 감추고 알림 영역에서 앱을 계속 실행합니다.

## 종료와 복구

`RecoveryJournal`은 숨길 창의 복구 정보를 먼저 디스크에 기록합니다. 임시 파일을 쓰고 디스크로 플러시한 뒤 원본을 교체하며, 기록을 완료하지 못한 창은 숨기지 않습니다. 작업 공간 구성의 영속 저장과는 별개입니다.

`ProcessLauncher`는 동일 실행 파일의 `--watch` 모드로 감시 프로세스를 시작합니다. 본 앱의 프로세스 ID와 시작 시간을 확인해 종료를 감지한 뒤 해당 기록에 대한 복구를 시도합니다. 본 앱은 시작 시 이전 실행의 고아 기록도 확인합니다. 정상 종료, 사용자의 복구 요청, 런타임 오류 처리에서도 복구를 요청합니다. 감시 프로세스가 먼저 종료되면 본 앱은 복구 후 일시 정지합니다.

복구 시에도 프로세스 식별 정보와 창 표식이 일치하는 경우에만 조작합니다. 이미 종료된 창이나 재사용된 핸들에 오래된 작업을 적용하지 않도록 하기 위한 검사입니다. 살아 있는 다른 앱 인스턴스의 기록은 `--recover`로 가져오지 않습니다. 복구되지 않은 창의 기록은 남겨 나중에 다시 시도할 수 있습니다.

데스크톱 수·이름·창 배정은 메모리에만 존재합니다. 앱을 다시 실행하면 모니터당 첫 데스크톱 하나로 시작합니다.

## 검증 범위

`IndependentVirtualDesktop.Core.Tests`는 외부 테스트 패키지 없이 실행하는 콘솔 검사기입니다. 서로 다른 모니터의 독립성, 연결 해제 시 창 이관, 데스크톱 삭제, 창 이동, 순환 전환, 입력 검증의 원자성, 스냅샷 분리를 검사합니다. 실패하면 0이 아닌 종료 코드를 반환합니다.

앱의 `--self-test <출력 폴더>`는 테스트용 창을 만들어 Windows API 경로와 작업 보기 렌더링을 검사합니다. 실제 키보드 훅을 설치하지 않으며 사용자의 기존 창을 제어 대상으로 사용하지 않습니다. `smoke-results.txt`와 `overview.png`를 출력합니다. 테스트 창이 잠시 화면에 표시되므로 로그인한 Windows 데스크톱 세션이 필요합니다.

두 물리 모니터에서 전용 테스트 창의 독립 전환, 소유 대화상자 동반 이동, 최소화 유지, 강제 종료 후 감시 프로세스 복구를 검증했습니다. 런타임을 포함한 배포본에서도 동일한 검사를 통과했습니다. 실제 전역 단축키 입력, 다양한 외부 앱, 모니터의 실제 연결 해제·재연결과 최대화 창의 호환성은 추가 확인이 필요합니다.
