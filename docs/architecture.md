# 구현 구조

제품명과 실행 파일은 `BetterVirtualDesktop`입니다. 이전 버전의 언어 설정·복구 기록을 계속 읽고 구버전과 중복 실행되지 않도록, 로컬 저장 경로와 창 복구 표식·뮤텍스 등 내부 호환 식별자는 `IndependentVirtualDesktop`을 유지합니다.

## 작업 공간 모델

`BetterVirtualDesktop.Core`는 Windows API에 의존하지 않는 .NET 10 라이브러리입니다. `WorkspaceCatalog`가 디스플레이별 데스크톱 목록과 활성 데스크톱 ID, 창별 배정을 소유합니다. 창이 속한 데스크톱과 해당 디스플레이의 활성 데스크톱이 같으면 논리적으로 표시할 창입니다.

| 모델 | 의미 |
| --- | --- |
| `DisplayDescriptor` | OS에서 발견한 디스플레이의 ID, 이름, 주 모니터 여부 |
| `WindowAssignment` | 창 핸들, 디스플레이 ID, 데스크톱 ID |
| `DesktopSnapshot` | 데스크톱 ID와 이름, 배정된 창 ID 목록 |
| `DisplaySnapshot` | 디스플레이 정보와 현재 데스크톱 ID, 데스크톱 목록 |

데스크톱 ID는 `Guid`, 창 ID는 `IntPtr.ToInt64()`에 대응하는 `long`입니다. 0인 창 ID는 거부하며, 부호 있는 포인터 표현을 보존하기 위해 음수인 비영 값도 허용합니다. 스냅샷은 내부 컬렉션과 분리된 읽기 전용 자료입니다. 카탈로그의 접근은 잠금으로 직렬화합니다.

자동으로 붙인 데스크톱 이름은 `DefaultNumber` 메타데이터로 구분하고 UI에서 현재 언어로 포맷합니다. 사용자 이름은 그대로 보관하므로 사용자가 직접 `Desktop 1` 같은 문자열로 이름을 지어도 언어 변경 시 번역하지 않습니다.

모니터 목록을 동기화할 때 입력 전체를 검증한 뒤 반영합니다. 빈 목록이나 중복 ID처럼 잘못된 입력은 현재 상태를 바꾸지 않습니다. 연결이 유지된 모니터는 데스크톱 구성을 유지하고, 새 모니터는 데스크톱 하나로 시작합니다. 연결 해제된 모니터의 모든 창은 남은 주 모니터의 활성 데스크톱으로 이동합니다. 주 모니터가 없다면 입력 목록의 첫 모니터를 사용합니다.

새 창의 발견은 `TrackWindow`가 처리하며, 이미 알려진 창을 다시 발견해도 배정을 바꾸지 않습니다. 사용자가 직접 다른 모니터로 옮긴 창에는 `AssignToDisplay`를 사용합니다. 명시적인 디스플레이·데스크톱 이동은 `MoveWindowsToDisplay`로 창 그룹 전체를 검증한 뒤 배정을 함께 갱신하며, 어느 디스플레이의 활성 데스크톱도 바꾸지 않습니다. 데스크톱 삭제는 창을 이전 데스크톱으로 옮기고, 첫 데스크톱이면 다음 데스크톱을 사용합니다. 마지막 데스크톱 삭제는 거부합니다. 상대 전환은 양방향으로 순환하며 `int` 전체 범위를 처리합니다.

## Windows 창 제어

`BetterVirtualDesktop.App`은 .NET 10 Windows Forms 앱입니다. 다음 순서로 사용자 창을 관리합니다.

1. `DesktopApplicationContext`의 500ms 타이머가 `DesktopController.Refresh`를 호출합니다.
2. `Screen.AllScreens`로 모니터를 동기화하고 `NativeWindows.EnumerateWindows`로 일반 앱 창과 연결된 대화상자를 수집합니다.
3. 새 창은 현재 Windows 기본 가상 데스크톱에 속하고 화면에 보이는 경우에만 등록합니다. 자체 앱 창, 쉘 창, 독립적인 도구 창 등은 제외합니다.
4. 창의 모니터 이동과 소유자 관계를 반영합니다. 연결된 대화상자와 보조 창은 소유자 창의 작업 공간을 따릅니다.
5. 카탈로그의 논리적 표시 상태를 `ShowWindowAsync`의 표시·숨김 요청으로 반영합니다.

Windows 공개 `IVirtualDesktopManager.IsWindowOnCurrentVirtualDesktop`는 현재 기본 데스크톱 여부를 확인하는 용도로만 사용합니다. Windows의 기본 가상 데스크톱을 생성·전환하거나 Explorer 작업 보기를 수정하지 않습니다. 이 앱의 데스크톱은 창 배정과 표시 상태로 구현한 별도의 작업 공간입니다.

창은 핸들만으로 식별하지 않습니다. 프로세스 ID, 프로세스 시작 시간, 창 클래스를 함께 확인합니다. 숨길 창에는 임의의 복구 표식을 `SetProp`으로 설정합니다. 프로세스 정보를 읽을 수 없거나 `SetProp`이 거부되면 해당 창을 숨기지 않습니다. 연결된 창 그룹의 일부를 안전하게 기록할 수 없으면 그룹 전체의 숨김을 피합니다. 따라서 일반 권한 앱에서 관리자 권한 창을 완전히 관리할 수 있다고 가정하지 않습니다.

`ShowWindowAsync`는 요청을 전달하는 API이므로 반환만으로 복구 완료를 판단하지 않습니다. 후속 가시성 확인까지 복구 기록을 유지합니다. 원래 최소화되어 있던 창은 최소화 상태로 복구하고, 일반·최대화 창은 저장된 배치를 유지하는 표시 방식을 사용합니다. 창 활성화는 Windows의 전경 활성화 정책에 영향을 받습니다.

`DesktopController.MoveWindowToDisplay`는 대상 디스플레이와 데스크톱, 창 식별 정보를 확인하고 소유 창·대화상자 그룹 전체를 이동합니다. 비활성 대상에 보낼 때는 먼저 그룹의 복구 가능성을 기록합니다. `NativeWindows.MoveGroupToDisplay`가 `GetWindowPlacement`로 읽은 정상 위치를 대상 작업 영역으로 변환한 뒤 비활성·비동기 `SetWindowPlacement`를 요청합니다. 최대화 창은 현재 최대화 영역도 대상 모니터로 맞춥니다. 최소화·최대화 상태와 그룹의 상대 배치를 유지하며, 작은 작업 영역에서는 그룹 크기를 함께 줄여 화면 안에 배치합니다. 일반 창의 작업 영역 좌표와 도구 창의 화면 좌표를 구분합니다.

창 이동 API의 성공 반환은 다른 프로세스가 요청을 받아들였다는 뜻입니다. 도착을 확인할 때까지 잠시 이동 상태를 추적하여 `Refresh`가 이전 좌표를 사용자의 역방향 이동으로 오해하지 않도록 합니다. 없는 대상이나 오래된 창 정보는 거부하고, 일부 네이티브 요청이 실패하면 이미 전달한 위치 변경의 복원을 시도합니다. 다른 프로세스가 닫히거나 응답하지 않을 수 있으므로 요청 수락을 모든 외부 앱의 이동 완료 보장으로 취급하지 않습니다.

## 작업 표시줄에서 창 선택

`TaskbarDesktopCoordinator`는 앱이 복구 기록을 갖고 숨긴 비활성 데스크톱의 일반 창을 공개 `ITaskbarList.AddTab`으로 작업 표시줄에 다시 등록합니다. 별도 대리 창을 만들거나 다른 앱의 스타일·AppUserModelID를 바꾸지 않고 원래 HWND를 사용하므로 Windows가 제공하는 앱 묶음과 개별 창 선택을 유지합니다. 소유 대화상자·독립 도구 창은 중복 버튼으로 추가하지 않습니다. 숨김 요청 후 최소 80ms와 실제 숨김을 확인한 뒤 등록하며 이미 숨긴 창에 `SW_HIDE`를 반복하지 않습니다. 단, 이전 비동기 표시 요청이 남아 있으면 숨김 요청을 뒤에 추가해 마지막 명령이 원하는 표시 상태가 되도록 합니다. 실제 `EVENT_OBJECT_HIDE`를 관찰해 폴링 사이의 표시·숨김으로 사라진 등록도 갱신하며 이 이벤트로 데스크톱을 전환하지 않습니다. `TaskbarCreated` 메시지를 받으면 Explorer의 등록을 복구합니다.

`ForegroundWindowHook`은 `SetWinEventHook(EVENT_SYSTEM_FOREGROUND, WINEVENT_OUTOFCONTEXT | WINEVENT_SKIPOWNPROCESS)`으로 실제 선택된 창과 이벤트 시각을 받습니다. 프로세스 이름이나 첫 번째 창으로 목적지를 추측하지 않습니다. UI 스레드로 넘긴 뒤 현재 전경 HWND·프로세스 ID·시작 시간·클래스·Windows 기본 데스크톱과 복구 기록을 검증하고, 해당 창이 속한 모니터의 데스크톱만 전환합니다. 같은 크롬 프로세스의 여러 창도 각 HWND에 저장된 배정을 따릅니다. 사용자가 복원한 최소화 창을 이전 최소화 상태로 되돌리지 않습니다.

단순 표시·알림 이벤트로는 전환하지 않습니다. 창 이동·전환·일시 정지 이전의 지연 이벤트는 세대와 시각으로 거부하며, 비동기 숨김이 진행 중이거나 숨김 완료 확인 이전에 발생한 포커스 이동도 무시합니다. 따라서 창을 옮기거나 숨기면서 Windows가 다른 창에 포커스를 주는 동작이 이전 데스크톱으로 돌아가게 만들지 않습니다. 일시 정지·단축키 설정 중에는 따라가기를 중단합니다.

창이 정상 표시 상태로 복원되면 작업 표시줄 소유권을 쉘에 돌려주며 `DeleteTab`으로 정상 버튼을 제거하지 않습니다. 닫힌 숨김 창의 수동 등록은 제거하고, 살아 있지만 식별 정보가 달라진 HWND는 건드리지 않습니다. 종료 시 복구 경로와 함께 훅·임시 등록을 정리합니다. 작업 표시줄의 숨겨진 창 미리보기 내용과 그룹 아이콘 한 번 클릭 시 어느 창을 선택할지는 Windows와 원래 앱이 결정하며, 실시간 썸네일을 보장하지 않습니다.

공개 API 근거: [ITaskbarList.AddTab](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-itaskbarlist-addtab), [SetWinEventHook](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook), [Windows 작업 표시줄](https://learn.microsoft.com/en-us/windows/win32/shell/taskbar).

## 작업 보기와 입력

`MoveWindowToNewDesktop`는 대상 모니터와 창 그룹의 식별 정보를 검증한 뒤 비활성 데스크톱을 만들고 기존 이동 경로를 사용합니다. 같은 모니터의 이동에도 그룹 전체의 복구 기록 준비를 적용합니다. 이동이 즉시 거부되면 이번 호출이 만든 빈 비활성 데스크톱만 제거합니다. 우클릭 메뉴와 새 데스크톱 카드의 드롭이 이 경로를 공유하며, 성공 후에도 각 모니터의 활성 데스크톱과 오버레이 미리보기 후보를 모두 유지합니다.

생성 성공 후 `ShowCreationFeedback`이 목적지 오버레이에 약 3.2초 동안 큰 생성 완료 안내를 표시하고, 새 카드가 보이는 경우 테두리를 강조합니다. 안내는 새 데스크톱 이름을 알려주지만 미리보기·카드 스크롤을 목적지로 바꾸지 않습니다. 비활성 데스크톱은 안내의 **데스크톱 열기** 버튼을 직접 눌러 전환할 수 있습니다. `Enter`는 계속 현재 미리보기 후보를 엽니다. 상단 제목은 미리보기 후보를 표시하고 그 아래에는 실제 활성 데스크톱을 별도로 표시합니다. 안내 애니메이션은 UI 타이머에서 갱신하며, 안내 종료는 카탈로그 상태나 창 배정에 영향을 주지 않습니다.

창 이동을 요청할 때 `PreservePreviewAfterMove`가 대기 중인 클릭을 취소하고 드롭 직후 마우스 놓기를 소비합니다. 커서가 데스크톱 목록을 벗어나기 전까지 호버로 미리보기를 바꾸지 않으므로, 목적지 카드 위에 남은 커서나 작은 움직임이 창을 따라 화면을 바꾸지 않습니다. 명시적인 카드 클릭·방향키 선택은 계속 사용할 수 있습니다. 다른 모니터로 이동할 때도 각 화면의 후보를 유지합니다.

기본 작업 보기는 연결된 디스플레이마다 하나씩 표시하는 테두리 없는 최상위 오버레이입니다. 각 창은 해당 화면 전체를 덮으며 중앙에 선택한 데스크톱의 창 미리보기를, 아래에 해당 디스플레이의 데스크톱 카드 목록을 표시합니다. 중앙 창은 종횡비를 반영해 배치하고, 아래 카드는 저장된 창 화면과 위치를 축소해 구성합니다. 실제 활성 데스크톱과 미리 보는 후보를 구분하며, 카드에 마우스를 올리거나 방향키로 후보를 바꾸어도 실제 데스크톱은 전환하지 않습니다.

앱 시작, `Win + Alt + Tab`, 알림 영역 아이콘 더블클릭과 오버레이 메뉴는 전체 오버레이를 여는 진입점입니다. 데스크톱 카드를 클릭하거나 `Enter`를 누르면 그 디스플레이만 전환한 뒤 모든 오버레이를 닫습니다. 창 미리보기를 클릭하면 그 창의 데스크톱으로 전환하고 활성화를 요청한 뒤 전체 오버레이를 닫습니다. `Esc`나 같은 단축키 반복 입력도 전체 오버레이를 닫습니다. 마우스가 진입한 오버레이로 키보드 포커스가 이동합니다. 데스크톱 추가·이름 변경·삭제도 오버레이에서 제공합니다. 닫힌 오버레이에서 늦게 전달된 선택 이벤트는 다시 연 오버레이의 세션에 적용하지 않습니다.

창 미리보기는 같은 화면 또는 다른 화면의 데스크톱 카드에 끌어 놓을 수 있습니다. 중앙 창 영역에 놓으면 그 오버레이에서 미리 보는 데스크톱이 대상이 됩니다. 드래그 데이터에 현재 오버레이 세션을 포함하여 이전 세션의 데이터를 받지 않으며, `OverlayCoordinator`가 디스플레이·데스크톱·창 정보를 컨트롤러로 전달합니다. 이동 성공 후에도 오버레이와 각 모니터의 활성 데스크톱은 유지됩니다. 창 우클릭 메뉴도 대상 디스플레이 아래에 데스크톱을 나열하여 동일한 이동 경로를 사용합니다.

`OverviewForm`은 알림 영역의 **관리 창**으로 유지합니다. 마우스가 위치한 모니터에 하나의 창으로 열리며 모든 모니터를 행으로, 각 모니터의 데스크톱을 카드로 표시하고 창 제목을 나열합니다. 데스크톱 제목을 우클릭하면 이름 변경·삭제 메뉴, 창 제목을 우클릭하면 대상 디스플레이 → 대상 데스크톱 이동 메뉴가 열립니다.

`KeyboardHook`는 별도 메시지 루프 스레드에서 저수준 키보드 훅을 실행합니다. `KeyboardShortcutState`가 물리 키의 눌림·떼짐 상태를 해석하고 명령을 발행하며, 명령은 UI 스레드로 전달됩니다. 주입된 키 입력은 단축키 판정에 사용하지 않습니다. 훅 콜백은 창 열거와 복구 파일 쓰기 작업을 직접 수행하지 않습니다.

초기 설정에서는 `Win + Tab`을 Windows에 전달하고 `Win + Alt + Tab`으로 앱의 작업 보기를 엽니다. `Win + Ctrl + ← / →`, `Win + Ctrl + D`, `Win + Ctrl + F4`는 마우스가 위치한 모니터의 데스크톱 전환·추가·삭제에 사용합니다. `Win + Ctrl + Shift + ← / →`는 전경 창의 기존 배정을 기준으로 창을 이동합니다. `Win + Ctrl + Shift + F12`는 전체 창 복구와 일시 정지를 요청합니다. 작업 보기의 창 선택은 해당 데스크톱으로 전환하지만, 창 이동 자체는 데스크톱 전환을 동반하지 않습니다.

단축키 설정은 오버레이·관리 창·알림 영역에서 열 수 있습니다. 각 명령을 Win/Ctrl/Alt/Shift와 일반 키의 조합으로 지정하거나 해제할 수 있으며, Windows 기본키 프리셋은 작업 보기를 `Win + Tab`으로 지정합니다. 저장 전에는 초안만 수정하고 저장에 성공하면 변경 사항을 즉시 훅에 적용합니다. 같은 조합의 중복 지정, 일반 키만 사용한 지정, 일부 보호된 시스템 조합은 거부합니다. 다른 앱의 모든 단축키 충돌을 탐지하는 기능은 아닙니다.

`ShortcutProfile`은 불변 매핑이며 훅 스레드와 UI 스레드는 입력 상태 변경을 동기화합니다. 설정을 변경해도 이미 앱이 소비한 키의 반복·해제는 끝까지 처리하여 입력 짝을 유지합니다. 설정 창이 열려 있는 동안 새 단축키 명령을 중단하고, 설정 후 새로 누른 키부터 새 매핑을 적용합니다. 대기 중인 명령도 매칭 당시의 설정 세대를 확인하여, 설정 창을 닫은 뒤 이전 입력이 실행되지 않게 합니다. 입력을 녹화하지 않고 체크박스와 키 목록으로 조합을 선택합니다.

일시 정지는 창 표시 정책만 바꿉니다. 키보드 훅과 설정된 단축키는 앱 종료까지 유지됩니다. `Win + Tab`을 앱에 지정하면 실행 중에는 Windows 기본 작업 보기 대신 자체 작업 보기를 엽니다. 오버레이와 관리 창의 닫기는 해당 UI만 감추고 알림 영역에서 앱을 계속 실행합니다.

## 현지화와 설정

`ShortcutPreferences`는 기존 `settings.json`의 `keyboardShortcuts` 항목을 읽고 씁니다. 언어와 다른 설정 필드를 보존하며 임시 파일을 교체하는 방식으로 저장합니다. 잘못된 값이나 불완전한 매핑은 전체 기본값으로 복구하고, 저장 실패 시 현재 단축키를 유지한 채 설정 창에 오류를 표시합니다. 단축키 이름·검증 메시지·설정 화면도 다섯 언어를 지원합니다.

`UiText`와 `UiTextResources`가 한국어(`ko`), 영어(`en`), 중국어 간체(`zh-Hans`)·번체(`zh-Hant`), 일본어(`ja`)의 문자열과 폰트를 제공합니다. 기본 선택은 Windows 표시 언어이며 지원하지 않는 언어는 영어로 처리합니다. 작업 보기와 트레이의 언어 메뉴는 각 언어의 고유 이름과 시스템 언어 사용 옵션을 제공합니다. 선택값은 `%LOCALAPPDATA%\IndependentVirtualDesktop\settings.json`에 로컬 저장하며, 이 설정은 실행 세션에만 유지되는 데스크톱 구성과 별개입니다.

언어 변경 이벤트는 트레이 메뉴·관리 창·현재 오버레이를 다시 그립니다. 이미 표시된 데스크톱 이름 알림도 갱신하되 만료 시간은 유지합니다. 카탈로그 재발견이나 창의 숨김·이동 경로를 호출하지 않으므로 활성 데스크톱과 창 배정은 바뀌지 않습니다. `DesktopName`은 기본 이름만, `DisplayName`은 물리 모니터 표시 이름을 현재 언어로 포맷합니다. 사용자 지정 데스크톱 이름과 외부 창 제목은 그대로 표시합니다. 테스트·fixture 실행은 한국어를 명시하되 사용자의 저장 설정을 읽거나 덮어쓰지 않습니다.

## Windows 로그인 시 자동 실행

트레이의 **Windows 시작 시 자동 실행**은 기본적으로 꺼져 있으며, 사용자가 켤 때 현재 실행 파일을 등록합니다. `StartupRegistration`은 현재 사용자의 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`에서 `BetterVirtualDesktop` 값만 관리합니다. 명령은 `"<실행 파일 전체 경로>" --startup` 형식의 `REG_SZ`이며, 끌 때 다른 앱의 값이나 키 자체는 삭제하지 않습니다. 경로의 공백·다국어 문자를 보존하고 호스트 실행 파일·상대 경로·너무 긴 명령은 등록 전에 거부합니다. [Windows Run 키 문서](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)에 따라 실제 실행 시점은 로그인 이후이며 Windows가 실행을 지연할 수 있습니다.

`--startup`으로 시작하면 트레이·단축키·복구 감시만 준비하고 오버레이는 열지 않습니다. 같은 앱이 이미 실행 중이면 알림창 없이 종료합니다. 직접 실행할 때는 기존처럼 오버레이를 표시합니다. 등록 상태를 별도 JSON에 중복 저장하지 않고 메뉴를 열 때 레지스트리에서 읽습니다. 현재 파일과 다른 경로가 등록되어 있으면 안내하고, 사용자가 다시 켤 때 현재 경로로 갱신합니다. 단순 실행·메뉴 열기·언어 변경은 등록을 수정하지 않습니다.

체크 표시는 현재 경로의 등록 여부입니다. Windows 설정의 **앱 → 시작 프로그램**에서 별도로 차단할 수 있으며, 앱은 그 설정을 강제로 변경하지 않습니다. `StartupSelfTests`는 실제 Run 키 대신 GUID로 구분한 임시 테스트 키에서 등록·삭제·외부 변경 반영·경로 갱신·다국어 메뉴를 검사하고 테스트 키를 정리합니다. 실제 로그아웃·재부팅은 자동 검증에 포함하지 않습니다.

## 창 미리보기

`DisplayOverlayForm`의 입력 대상은 화면을 다시 그릴 때 생성되는 콜백 객체가 아니라 창 핸들·데스크톱 ID·버튼 종류로 구분합니다. 눌린 대상의 ID와 놓은 대상의 ID가 같을 때만 실행하므로, 창 목록 재배치나 타이머 갱신이 다른 항목의 클릭으로 이어지지 않습니다. 포인터가 나가면 강조와 눌림 렌더링을 해제하고, 포커스·마우스 캡처를 잃거나 대상이 사라지면 대기 중인 클릭을 취소합니다. 드래그 시작 시 눌림을 정리하고 드래그 후 마우스 놓기를 클릭으로 처리하지 않습니다.

호버 강조는 16ms 타이머에서 약 0.12초 동안 전환하고 안정된 상태에서는 타이머를 멈춥니다. 눌림은 즉시 표시합니다. DWM이 그리는 창 내용 바깥에 여백과 제목 영역을 두어, 실시간 미리보기 위에서도 테두리와 누름 표시를 볼 수 있게 합니다. 다시 그릴 때는 포인터 위치와 새 배치로 강조 대상만 확인하며, 데스크톱 미리보기 후보 변경은 실제 마우스 이동이나 키보드 입력에서만 수행합니다.

`DwmThumbnailSession`은 보이는 비최소화 창에 대해 `DwmRegisterThumbnail`과 `DwmUpdateThumbnailProperties`를 사용합니다. DWM이 오버레이의 최상위 HWND에 원본 창의 클라이언트 영역을 직접 합성하며, 갤러리 변경·오버레이 종료 시 등록을 해제합니다. 이 합성 결과는 GDI의 `DrawToBitmap`에는 포함되지 않습니다. Windows 기본 Task View UI를 수정하거나 다른 앱에 코드를 주입하지 않습니다.

`WindowPreviewCache`는 보이는 정상 창을 별도 작업 스레드에서 `PrintWindow`로 캡처합니다. 숨겨지거나 최소화된 창은 새로 캡처하지 않고 이전에 확보한 화면을 재사용하며, 미리보기를 위해 창을 표시하지 않습니다. 프로세스 ID·시작 시간·창 클래스가 달라지거나 창이 사라지면 관련 이미지를 폐기합니다. 보호된 콘텐츠, 응답하지 않는 창, 지원되지 않는 캡처와 검은 화면은 캐시에 넣지 않습니다. 사용 가능한 이미지가 없으면 제목과 안내 문구가 남습니다.

이미지는 메모리에만 보관합니다. 유지 캐시는 최대 48장·총 1,200만 픽셀, 완료 대기 이미지는 별도로 총 1,200만 픽셀까지 제한합니다. 각 캐시 이미지는 최대 960×600으로 축소하며 한 번에 캡처할 원본도 최대 1,600만 픽셀로 제한합니다. 같은 창의 캡처 요청에는 최소 1초 간격을 둡니다. `PrintWindow`가 다른 프로세스 내부에서 멈출 수 있으므로 작업 스레드는 하나만 만들고, UI와 종료 처리는 그 스레드의 완료를 기다리지 않습니다. 따라서 한 앱이 전체 스냅샷 갱신을 지연시킬 수 있어도 UI 스레드를 막거나 작업 스레드를 계속 추가하지 않습니다.

숨겨진 창의 이미지는 마지막 화면이며 실시간 내용이 아닙니다. Windows 기본 작업 보기의 전환 애니메이션, 모니터별 배경화면과 독립적인 작업 표시줄은 구현 범위에 포함하지 않습니다.

## 데스크톱 이름 알림

`DesktopNameToastCoordinator`는 컨트롤러의 변경 이벤트에서 각 디스플레이의 활성 데스크톱 ID를 비교합니다. 전환한 디스플레이에만 `DesktopNameToastForm`을 약 1.8초 표시하고 마지막 0.2초에 흐리게 닫습니다. 연속 전환은 최신 이름으로 갱신하며, 창 목록 새로 고침은 표시 시간을 늘리지 않습니다. 시작 시와 같은 데스크톱 재선택 시에는 알림을 표시하지 않습니다.

알림은 기본적으로 모니터 작업 영역의 오른쪽 위에 표시하며, 트레이 메뉴에서 왼쪽 위로 바꿀 수 있습니다. 선택한 위치는 실행 중에만 유지됩니다. `WS_EX_NOACTIVATE`, `WS_EX_TOOLWINDOW`, 투명 계층 창 스타일과 비활성 표시를 사용해 작업 표시줄에 나타나거나 키보드 포커스를 가져가지 않고 클릭을 통과시킵니다. 모니터별 DPI와 음수 화면 좌표를 반영하며 일시 정지·종료·모니터 제거 시 알림을 정리합니다.

통합 검사에서는 전환한 모니터에만 표시, 포커스 유지, 작업 영역 내 배치, 왼쪽 위로 위치 변경, 연속 전환·이름 변경 반영, 새로 고침 중 자동 사라짐을 확인합니다. 렌더링 결과는 `desktop-name-toast.png`로 저장합니다.

## 종료와 복구

`RecoveryJournal`은 숨길 창의 복구 정보를 먼저 디스크에 기록합니다. 임시 파일을 쓰고 디스크로 플러시한 뒤 원본을 교체하며, 기록을 완료하지 못한 창은 숨기지 않습니다. 작업 공간 구성의 영속 저장과는 별개입니다.

`ProcessLauncher`는 동일 실행 파일의 `--watch` 모드로 감시 프로세스를 시작합니다. 본 앱의 프로세스 ID와 시작 시간을 확인해 종료를 감지한 뒤 해당 기록에 대한 복구를 시도합니다. 본 앱은 시작 시 이전 실행의 고아 기록도 확인합니다. 정상 종료, 사용자의 복구 요청, 런타임 오류 처리에서도 복구를 요청합니다. 감시 프로세스가 먼저 종료되면 본 앱은 복구 후 일시 정지합니다.

복구 시에도 프로세스 식별 정보와 창 표식이 일치하는 경우에만 조작합니다. 이미 종료된 창이나 재사용된 핸들에 오래된 작업을 적용하지 않도록 하기 위한 검사입니다. 살아 있는 다른 앱 인스턴스의 기록은 `--recover`로 가져오지 않습니다. 복구되지 않은 창의 기록은 남겨 나중에 다시 시도할 수 있습니다.

데스크톱 수·이름·창 배정은 메모리에만 존재합니다. 앱을 다시 실행하면 모니터당 첫 데스크톱 하나로 시작합니다.

## 검증 범위

`BetterVirtualDesktop.Core.Tests`는 외부 테스트 패키지 없이 실행하는 콘솔 검사기입니다. 서로 다른 모니터의 독립성, 연결 해제 시 창 이관, 데스크톱 삭제, 창 이동, 순환 전환, 입력 검증의 원자성, 스냅샷 분리를 검사합니다. 실패하면 0이 아닌 종료 코드를 반환합니다.

앱의 `--self-test <출력 폴더>`는 테스트용 창을 만들어 Windows API 경로와 오버레이·관리 창 렌더링을 검사합니다. 실제 키보드 훅을 설치하지 않으며 사용자의 기존 창을 제어 대상으로 사용하지 않습니다. `artifacts\tests`를 출력 폴더로 사용하면 결과는 `smoke-results.txt`, 오버레이 이미지는 `overlay-primary.png`, `overlay-2.png`, `overlay-compact.png`, `overlay-hidden-desktop.png`, 관리 창 이미지는 `overview.png`입니다. 테스트 창이 잠시 화면에 표시되므로 로그인한 Windows 데스크톱 세션이 필요합니다.

Release 빌드와 코어 검사 12개, 단축키 판별과 모니터 간 창 배치 계산 등 네이티브 순수 로직 검사 33개 그룹이 통과했습니다. 두 물리 모니터의 통합 검사에서는 모니터당 오버레이 하나, 정확한 화면 경계, 해당 모니터의 카드·창만 표시, 마우스 진입에 따른 포커스 이동을 확인했습니다. 전환 없는 후보 탐색, `Esc`와 토글의 전체 닫기, 이전 세션의 지연 선택 이벤트 무시, 선택한 모니터만 전환되고 다른 모니터의 창은 유지되는 동작도 확인했습니다.

전용 테스트 창의 소유 대화상자 그룹을 다른 물리 모니터로 보내고, 활성 데스크톱 유지와 `Refresh` 이후 배정 유지를 확인했습니다. 비활성 대상에서의 숨김·전환 후 복구, 최소화·최대화 상태 유지, 원래 모니터와 데스크톱으로 복귀, 없는 모니터·삭제된 데스크톱·미등록 창의 거부, 강제 종료 후 감시 프로세스 복구 검사도 통과했습니다.

미리보기 검사에서는 각 화면의 DWM 썸네일 등록과 캐시 이미지 생성을 확인하고, 비활성 데스크톱의 미리보기를 탐색해도 원본 창이 숨겨진 상태를 유지하는지 검사했습니다. 드래그 이벤트를 수신 경로에 전달하여 다른 모니터로 창이 이동하면서 오버레이와 활성 데스크톱이 유지되는지, 이전 오버레이 세션의 드래그 데이터가 무시되는지도 확인했습니다.

기본 프로필의 `Win + Alt + Tab` 판별·일반 `Win + Tab` 통과와 Windows 프리셋의 `Win + Tab` 처리를 순수 로직에서 검사합니다. 사용자 지정 조합, 키가 눌린 상태의 설정 변경·중단·재개, 키 해제 순서, 임시 파일을 통한 설정 저장·복원과 언어 설정 보존도 검사합니다. 설정 화면의 저장·취소·저장 실패·중복 오류를 확인하고 다섯 언어와 최소 크기 렌더링을 `shortcuts-*.png`로 저장합니다. 실제 마우스로 시작해 모니터 경계를 지나 놓는 전체 드래그 동작, 전역 단축키 입력과 Windows 기본 작업 보기의 상호 작용은 수동 검증이 필요합니다. 다양한 외부 앱의 이동·미리보기, 보호된 콘텐츠, 모니터의 실제 연결 해제·재연결도 추가 확인 대상입니다.

작업 표시줄 전환·자동 실행 옵션과 창 이동 후 화면 유지까지 적용한 최신 런타임 배포 폴더는 `artifacts\taskbar-publish`이며 실행 파일은 `BetterVirtualDesktop.exe`입니다. Release 빌드와 코어 12개·앱 자체 검사 260개가 통과했습니다. 앱 검사에는 자동 실행 21개, 창 이동 후 미리보기 유지 6개, 작업 표시줄 연결과 개별 창 활성화 22개 검사가 포함됩니다. 전체 결과는 `artifacts\tests\smoke-results.txt`에 있습니다.

`scripts\test.ps1 -MovesOnly`는 숨겨진 테스트 폼에 드래그·클릭·키 입력을 전달해 기존·새 데스크톱으로 이동, 드롭 직후 마우스 이동·해제, 스냅샷·언어 갱신 이후에도 활성 데스크톱과 미리보기·목록 위치가 유지되는지 검사합니다. 카드 클릭과 방향키·Enter, 생성 알림의 데스크톱 열기도 확인합니다. 실제 창·포인터·전역 키보드 훅은 조작하지 않습니다. 배포본에서도 같은 6개 그룹이 통과했으며 결과는 `artifacts\move-stay-publish-tests\move-results.txt`에 있습니다. `-StartupOnly`로는 실제 시작 프로그램을 변경하지 않는 자동 실행 검사를 별도로 실행할 수 있습니다.

`scripts\test.ps1 -TaskbarOnly`는 전용 하위 프로세스 창만 대상으로 같은 앱의 서로 다른 창·소유 대화상자·최소화 창·다른 모니터·일시 정지·오래된 이벤트·진행 중인 숨김과 이동을 검사합니다. 실제 작업 표시줄 등록 API와 테스트 프로세스만 관찰하는 WinEvent 훅도 사용합니다. Windows의 전경 권한을 위해 임시 `BetterVirtualDesktop taskbar activation test` 창을 활성화해야 할 수 있습니다. 자동 검사의 선택은 검증용 창의 표시·활성화 API를 호출하며 실제 작업 표시줄 마우스 클릭을 자동화하지 않습니다. 사용자 확인에서는 작업 표시줄의 테스트 창이 열리는 동작이 보고되었습니다. 여러 Chrome 프로필·외부 앱별 실제 썸네일 클릭과 Explorer 재시작은 별도 실사용 검증 대상입니다.

배포본에서도 작업 표시줄 관련 22개 검사가 통과했습니다. 결과는 `artifacts\taskbar-publish-tests\taskbar-results.txt`에 있습니다.

전체 검사는 순수 로직·설정 저장·UI·실제 Windows API 통합 검사를 포함하며 실제 전역 키보드 입력은 실행하지 않습니다. 이번 최종 전체 실행은 모두 통과했습니다. 다국어 렌더링 이미지는 `artifacts\tests`, 아이콘 확인 이미지는 `artifacts\icon-check`에 있습니다. 기존 실행 중인 배포본은 덮어쓰지 않습니다.

`Assets/BetterVirtualDesktop.ico`는 실행 파일의 Windows 리소스(`ApplicationIcon`)와 관리 리소스(`EmbeddedResource`)에 포함합니다. `AppIcon`은 내장 리소스에서 창·트레이 크기의 공유 아이콘을 한 번씩 로드하므로 현재 디렉터리나 외부 이미지 파일에 의존하지 않습니다. 소비하는 폼과 트레이가 닫혀도 공유 아이콘은 프로세스 수명 동안 유지합니다. ICO에는 16~256픽셀의 10가지 크기와 알파 채널이 들어 있습니다.

`build.ps1 -Publish`는 배포 후 `copy-runtime-notices.ps1`을 실행합니다. 실제 포함된 .NET 런타임 버전을 읽어 해당 NuGet 패키지의 라이선스·제삼자 고지를 배포 폴더의 `licenses`에 원문 그대로 동봉합니다. 이는 앱 자체의 라이선스 선택과 별개입니다.
